# Consigna de ejecución — RedNova

Miércoles 28 de octubre de 2026. Trabajen con una copia extraída del paquete completo. El objetivo es producir y explicar una propuesta de reposición reproducible y conservar sus versiones. No se emite ningún pedido. La guía autónoma está en `material/Clase_08_Miercoles_Docker_del_Pipeline.pdf`.

**Antes de clase:** completar `PREPARACION_ANTES_DE_CLASE.md`. Instalaciones y descarga inicial de Docker están fuera de los 90 minutos.

| Tiempo | Etapa | Evidencia | Qué explicar |
|---|---|---|---|
|0–8|1. Abrir carpeta/terminal y comprobar herramientas.|Modalidad y versiones.|Dónde se ejecutan comandos y quién ejecuta.|
|8–23|2. Seguir GUIA_GIT y registrar la base.|Primer commit, log y estado limpio.|Guardar, add y commit.|
|23–38|3. Reconocer fuentes y ejecutar local_v1.|Informe, calidad y cierre.|Grano, uniones y cálculo 2900/2150/750.|
|38–48|4. Revisar M0 y reposición.|Pronóstico, manifiesto y cantidades.|140 unidades previstas y propuesta 70 sujeta a revisión.|
|48–68|5. Construir/ejecutar Docker y comparar.|Corrida docker_v1 y comparación.|Imagen, contenedor, montajes, coincidencias y metadatos distintos.|
|68–82|6. Documentar escenario, registrar segundo commit y ejecutar v2.|Diff revisado, commit y escenario_v2.|Políticas ya provistas; A100: 70→90; B200: 0→0; C300: 8→10.|
|82–90|7. Completar respuestas y crear entrega.|ZIP local del equipo.|Verificación personal, agentes y pendientes.|

Si no funciona Docker, identifique el problema y siga con Git y Python local. Una demostración docente se declara observada; si no se ejecutó, queda pendiente. Nunca sustituya evidencia Docker por una ejecución local con otro nombre.

Las pruebas automáticas pueden demostrarse o ejecutarse después: `python3 -m unittest discover -s tests -v`. M1 (entrenamiento y evaluación temporal) es ampliación opcional, no requisito del núcleo de 90 minutos.
